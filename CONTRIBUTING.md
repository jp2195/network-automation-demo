# Contributing / developing

A short guide for *modifying* the lab. To just run it, see
[GETTING-STARTED.md](GETTING-STARTED.md).

Before a change, run `make doctor` to confirm your host can run the stack,
and remember that the cluster deploys from Git: to test changes end to end,
push them to a fork or branch and point the cluster at it with
`make repoint REPO=<git url> REV=<branch>` (see the
[README Quickstart](README.md#quickstart)).

## The one rule: a lot of files are generated — don't hand-edit them

Most of `workloads/*` is rendered from a single spec (`spec/atlanta.yaml`) by the
Go renderer in `tools/render/`. Generated files carry a banner:

```text
# Generated by tools/render — do not edit. Source: spec/atlanta.yaml + tools/render/*.
```

Edit the **renderer or the spec**, not the output. Then:

```bash
make render          # regenerate workloads/* from spec/atlanta.yaml
make render-check     # re-render to /tmp and fail on any drift or missing banner
```

`make render-check` re-runs the renderer into `/tmp/render-check`, diffs every
renderer-emitted file against the committed copy, and checks each one still
carries the banner. If it reports `DRIFT`, your change went into a generated
file — move it into `tools/render/*` (or the embedded
`tools/render/templates/*.tmpl`) and re-render. The full list of rendered
outputs is in [docs/architecture.md](docs/architecture.md#re-rendering-from-spec).

CI enforces the same rule: it runs `go run ./tools/render` and fails on any
`git diff`, so a hand-edit to a generated file can't merge.

Hand-maintained (safe to edit directly): the `bin/*` scripts, the eventing
**Python** in `workloads/eventing/scripts/`, the Argo `Sensor`/`EventSource`
YAML in `workloads/eventing/` that has *no* banner, the dashboards' JSON
(except `geomap.json`, which is rendered, and the cross-dashboard links the
renderer rewrites), the Helm values in `platform/values/`, the Dockerfiles in
`images/`, and the docs.

## CI

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs on every push and
pull request:

- `go vet` and `go test` for the renderer and the console
- the render drift gate (`go run ./tools/render` + `git diff --exit-code`)
- the Python unit tests for the eventing scripts
- `shellcheck` on the shell scripts
- a build of the console image

Run the equivalent locally before opening a pull request:

```bash
go vet ./... && go test ./...
make render-check
shellcheck bin/*.sh
```

## Tests

```bash
# Go — the renderer + console (golden tests cover the rendered output)
go test ./...

# Python — the eventing scripts (enrich/analyze/notify, drift, remediate, AI…).
# Each test file's header gives its exact command. Pure-stdlib suites run direct:
cd workloads/eventing/scripts && python3 -m unittest test_analyze_impact -v
# Others need extra deps via uv, e.g.:
#   uv run --with fakeredis --with valkey python3 -m unittest test_drift -v

# …or run every eventing suite at once with the union of those deps:
cd workloads/eventing/scripts && uv run --quiet \
  --with fakeredis --with valkey --with "pydantic-ai-slim[openai]" \
  --with fastapi --with httpx python3 -m unittest discover -p "test_*.py"

# dom-synth lives in its own directory and needs valkey + fakeredis:
cd workloads/dom-synth && uv run --quiet --with valkey --with fakeredis \
  python3 -m unittest test_dom_synth
```

After changing eventing Python, the change reaches the cluster two ways: the
`workflow-scripts` ConfigMap (mounted over `/scripts` at runtime — a deploy/sync
picks it up) and the pre-baked images. If you changed a *dependency* (not just
code), rebuild the image: `make build` (or the single `docker buildx build … ai-analyst …`
line in the Makefile).

## Regenerating the docs GIFs

The GIFs are recorded headless, not hand-captured, so they stay current:

```bash
brew install ffmpeg    # macOS; use your package manager elsewhere
npm --prefix tools/gifgen ci          # Playwright (+ its Chromium)
bin/make-gif.sh                       # geomap reacting to a fiber cut -> docs/assets/grafana-fault.gif
# override: DASH=geomap NODE=hub-e INTERFACE=ethernet-1/2 OUT=docs/assets/grafana-fault.gif bin/make-gif.sh

# scenario mode — record a whole canned storyline (cascade + self-heal):
SCENARIO=hurricane OUT=docs/assets/grafana-scenario.gif bin/make-gif.sh
```

Scenario mode records the full topology (`HEIGHT` defaults high) through a
`bin/scenarios.sh` run. Heads-up: the geomap on a fast kiosk refresh can OOM a
default-sized Grafana — the recorder uses a gentler `REFRESH` and the chart value
is bumped to 768Mi (see the runbook's "Grafana OOMKilled" entry).

It logs into the live Grafana, records a dashboard while a scripted fault runs,
and assembles the GIF with ffmpeg. The cluster must be up (`make ready` green).
